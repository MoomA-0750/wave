# Connect v2 の中継の運用（Phase 6b）

中継 v2 は、家の端末一覧（署名付きの記録の鎖）と、暗号化した最新の再生状態を持つ（`dev/active/phase6b-plan.md`、ADR-0010 予定）。
中継は中身を読めない。ここに書くのは、中継を動かす人（本人）が general-console で行う操作だけ。

## 起動

配布物（`relay/build/install/relay`）を Docker のコンテナで動かす（例は `dev/relay-deploy-v2/compose.yaml`）。中継は v2 だけになった（v1 は 2026-10-14 に消した）。`WAVE_RELAY_PROTOCOL=v2` が無いと起動しない。

| 環境変数 | 値 |
|---|---|
| `WAVE_RELAY_PROTOCOL` | `v2`（必須。v1 のコンテナが新しい配布物で起き直したときに、はっきり止めるため） |
| `WAVE_RELAY_HOST` | 端末の設定（`wave.relayV2Host`）と同じホスト名とポート。署名の対象に入る |
| `WAVE_RELAY_DATA` | 家のファイル（Docker のボリューム上）。v1 の登録ファイル（`registry.json`）は読めないので指さない |
| `WAVE_RELAY_BOOTSTRAP_KEYS` | 家を作れる端末の署名公開鍵（base64url の SPKI）。家が無い間は、この端末だけが接続できる |
| `WAVE_RELAY_PORT` / `WAVE_RELAY_BIND` | 待ち受け。`tailscale serve` からだけ届くようにする |

- 家のファイルがあるのに読めない・鎖を検証できないときは、起動を止める（`storeId` を作り直すと、全端末に「サーバーの状態が作り直されました」と出るため）
- コンテナを再起動しても `storeId` は変わらない（ファイルに保存している）

## 家を消して作り直す（決定 L-13）

アプリからは家を消せない。次のときだけ、general-console で行う。

- 家を作った端末（起動時の設定の鍵の端末）を入れ直して、身元の鍵が変わった
- 家の端末をすべて失った・鎖が壊れた

手順:

1. 中継 v2 のコンテナを止める
2. 新しく家を作る端末の署名公開鍵に、`WAVE_RELAY_BOOTSTRAP_KEYS` を替える（入れ直した端末なら、アプリの debug の `connect_info` で書き出した値）
3. 家を消す: `WAVE_RELAY_PROTOCOL=v2 WAVE_RELAY_DATA=<家のファイル> relay household-reset`
4. コンテナを起動する
5. 起動時の設定の鍵の端末で家を作り、ほかの端末を QR と6桁で加え直す

消すと、全端末で「サーバーの状態が作り直されました」が出る。端末は、本人が押すまでその状態で止まったり取り込んだりしない（決定 L-12）。

## 端末を失ったとき

家の player の端末の「端末の連携」の画面に、家の端末の一覧と「外す」がある（他の端末だけ。この端末自身を外す操作はまだ無い）。
中継はその端末の接続を切り、以後の認証を断る。再生中の端末は、次の書き込みを待たずに、外した端末を宛先から外して状態を書き直す。

外された端末の画面には「中継がこの端末を家の端末として受け付けません」と出る。本人が「この端末の家の記録を消す」を押したときだけ消える（勝手には消さない。中継の家を作り直したときも同じ表示になる）。

端末の名前は鎖にも中継にも入れない。加入のときに相手から聞いた名前を、その2台がそれぞれ覚えるだけなので、3台目からは「端末 xxxxxx」（ID の頭）と表示される。

## 端末の保存を作り直したとき

端末の「Connect v2 の保存を読めません」→「作り直す」の後は、その端末は家の記録を失う（Keystore の鍵は残る）。
もう一度 QR と6桁の手順を行えば家に戻れる。鍵が同じなので、加える側は鎖に追記せず、加わる側は6桁で確かめた頭の鎖に自分がいることを確かめて受け入れる。
