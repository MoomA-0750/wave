# ダウンロードとスマートダウンロード

状態: 採用（2026-10-23、本人の回答。「全端末いっぺんに」「ポッドキャストのエピソード・高く評価した曲・1曲ずつ・プレイリスト・アルバム」「YouTube Music に基本従いつつ、おすすめ、聞いたことないけど好きそう、いつも聞いてるようなものを実にまばらにとって、画面もそれでカテゴリ分けして選べるように」「通信は設定で決められるように」）

## 背景

曲の音は端末に残している（上限 300MB、最後に使ったのが古い曲から消す）が、これは早く鳴らすための置き場で、消えてよいもの。通信の無い所（地下・飛行機）でも聴けるよう、本人が選んだものを消えない置き場に取っておきたい。YouTube Music のスマートダウンロード（聴きそうな曲を自動で取っておく）も欲しい。

調べた時点の各端末（Android は Kotlin の core と androidApp、Mac・iPhone は Swift の WaveCore、Windows は C# の Wave.Core）には、ダウンロードの考え・通信の種類（従量制かどうか）の見分け・端末の中の再生回数の記録が、どれも無い。音の取り方（StreamResolver）と、曲の形式と頭からのバイトを残す置き場（AudioCache。Android は Media3 の SimpleCache）は、3つともほぼ同じ形で持っている。

## 決定

### 何を取れるか

1. **1曲ずつ・プレイリスト・アルバム・高く評価した曲・ポッドキャストのエピソード**（YouTube のポッドキャストのエピソードは曲と同じく videoId で取る。RSS のエピソードは音声の URL から取る）
2. **プレイリスト・アルバム・高く評価した曲は「丸ごと」を覚え、中身を合わせ続ける**。起動したとき・ページを開いたとき・1日1回、一覧を読み直し、増えた曲を取り、外れた曲を消す（ほかの理由でも取っている曲は残す）
3. **ライブ配信は取らない**

### 置き場

4. **消えない置き場に、曲ごとに音のファイルと形式を置く**。速く鳴らすための置き場（AudioCache）とは別にし、上限で消さない
   - Android: `filesDir/downloads`、Mac・iPhone: Application Support の `wave/downloads`（iPhone はバックアップから外す）、Windows: `%LOCALAPPDATA%\wave\downloads`
   - 曲は `<videoId>.bin` と `<videoId>.json`（AudioCache の形式に、取り終えた印と、通信なしで一覧を出すための曲の情報を足したもの）。RSS のエピソードは音声の URL の SHA-256 を名前にする
   - 何を取っているかの目録は `downloads.json` に置く: 丸ごとのもの（種類・id・題・画像・足した時刻・曲の並び）、1曲ずつのもの、スマートダウンロードの曲（分類つき）。曲のファイルは、どれか1つでも持ち主がいれば残す
   - 署名付きの URL は書かない（AudioCache と同じ）
5. **音質は再生と同じ**（Premium の高音質。AAC 256kbps か opus）。取るたびに URL を調べ直し、403 なら調べ直してやり直す
6. **鳴らすときは、取り終えた曲を最初に見る**。通信もしないし、URL も調べ直さずに鳴らす（再生履歴を YouTube に送るための URL の調べは、通信できるときだけ裏で行う）

### 取り方

7. **取るのは1つずつ、待ち行列で**。アプリが動いている間に取る
   - Android は JobScheduler（ReleaseWatcher と同じ）で、取り残しと1日1回の入れ替えも行う
   - iPhone は BGProcessingTask（`xyz.mooma0750.wave.downloads`）で1日1回の入れ替えを行う
   - Mac・Windows は動いている間だけ、6時間ごとに確かめる
8. **使う通信は設定で決める**（「ダウンロードに使う通信」: 「Wi-Fi など従量制でない通信だけ」（既定）／「どの通信でも」）。手で選んだものも、スマートダウンロードも同じ設定に従う。合わない通信の間は待ち、合う通信になったら続ける
   - 従量制かどうかは OS に聞く: Android は `NET_CAPABILITY_NOT_METERED`、Mac・iPhone は `NWPathMonitor` の `isExpensive` / `isConstrained`、Windows は `ConnectionProfile` の通信料の種類（`Unrestricted` 以外は従量制）
9. **ログアウトすると全部消す**（AudioCache と同じく、ほかのアカウントに前のアカウントの音を残さない。ADR-0007）

### スマートダウンロード

10. **3つの分類から同じ数ずつ取る**。設定で入り切りでき（既定は切）、曲数を選ぶ（25・50・100・200。既定は 50）
    - **いつも聴いている**: この端末での再生回数（新しく記録を始める。曲ごとの回数・最後に聴いた時刻・曲の情報。2000 曲まで、古いものから忘れる）と、YouTube の再生履歴（FEmusic_history）に出る曲。回数の多い順、同じなら新しい順
    - **好きそう（聴いたことのない曲）**: 「いつも聴いている」の上位の曲（5曲まで）を種にしたラジオ（`RDAMVM<videoId>`）から、再生回数・再生履歴・高く評価した曲に無い曲だけを、種ごとに順番に取る
    - **おすすめ**: ホームの1ページ目の棚のうち曲が並んだ棚（「おすすめ」など）の曲。足りなければ、ホームの最初のミックス（プレイリスト）の曲
11. **まんべんなく取る**: 3つの分類から1曲ずつ順番に取り、同じアーティストは全体で2曲まで、分類どうしで重なった曲は先に入った分類に入れる。どれかの分類が足りなければ、ほかの分類で埋める
12. **1日1回選び直す**。選び直して外れた曲は消し、新しく入った曲を取る（手で取っている曲は消さない）
13. **画面は分類で分けて選べる**: ダウンロードの画面のスマートダウンロードの所に「すべて・いつも聴いている・好きそう・おすすめ」を出し、選んだ分類の曲を並べて、丸ごと再生・シャッフルできる

### 画面

14. **マイライブラリに「ダウンロード」を置く**（「高く評価した曲」と同じく、いつも先頭の方に出す）。開くと:
    - スマートダウンロード（入り切り・分類・曲）
    - 丸ごと取っているもの（プレイリスト・アルバム・高く評価した曲・エピソード。それぞれ取り終えた数）
    - 1曲ずつ取った曲
    - 使っている容量と、取っている途中の進み具合
15. **プレイリスト・アルバム・高く評価した曲のページの頭に、ダウンロードのボタン**（取っていない／取っている途中（何曲中何曲）／取り終えた、の3つの見た目。取っているものを押すと、消すか確かめる）
16. **曲・エピソードのメニューに「ダウンロード」「ダウンロードを削除」**。取り終えた曲の行には小さな印を出す
17. **設定に「ダウンロードに使う通信」「スマートダウンロード」（入り切りと曲数）「ダウンロードをすべて削除」と、使っている容量**

### 通信できないとき

18. **通信できないとき、取っていない曲は飛ばして、取った曲へ進む**（今の「通信の失敗では飛ばさずに止める」の例外。取った曲が1つも無ければ今と同じく止める）。ダウンロードの画面と、取ったプレイリスト・アルバムのページは通信なしでも開ける

### 時計

19. **時計（Wear OS）には取らない**（時計はスマホの操作が主で、自分で鳴らすのは今もスマホ経由のため）

## 結果

- 端末ごとに取る（端末の間で「何を取ったか」は合わせない）。本人が端末ごとに選ぶ
- 再生回数はこの端末で聴いた分だけ。ほかの端末で聴いた分は、YouTube の再生履歴を通して入る
- Android は Media3 の SimpleCache ではなく、ほかの端末と同じくファイルで持つ（目録を4つで同じ考えにし、通信なしで一覧を出すため）
- iPhone・Android で、アプリを閉じている間の大量の取得は OS が止めることがある。次に開いたときか、OS が仕事を回したときに続ける
