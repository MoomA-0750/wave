# RSS の登録と聴いたところを、Connect の中継で家の端末の間で合わせる

状態: 採用（2026-10-13、本人が「Connect の中継」を選んだ）

## 背景

ADR-0012 で、RSS のポッドキャストの登録と聴いたところを端末ごとに覚えることにした。本人から「端末の間で同期したい」と頼まれた。YouTube のアカウントには置き場が無い。置き場の候補は、Connect v2 の中継（ADR-0010）と、YouTube の非公開のプレイリストの説明欄だった。本人は中継を選んだ（説明欄は5000字で、聴いたところを持てない）。

## 決定

1. **中継に「ライブラリ」の文書を1つ持たせる**（`DocKind.Library`、`LibraryBody`）。中身は、フィードの URL ごとの番組（題・作者・画像・登録した時刻・外した印）と、音声の URL ごとの聴いたところ。Connect の他の文書と同じく、家の端末ごとの鍵で包み、書き手が署名する。中継は中身を読めない
2. **配るのは `library_get` を送った接続だけ**。古い版の端末に、知らない命令・知らない種類の文書を流さない。命令は `library_get`・`library_put`・`library_ok`・`library_conflict`・`library` の5つ
3. **家のどの端末も書ける**（再生中でなくてよい。操作だけの端末も書ける）。版の CAS で、食い違ったら届いた最新と合わせて書き直す
4. **合わせ方は、番組・エピソードごとに更新した時刻の新しい方を残す**（同じなら中継の側）。外した番組は「外した印」として残し、古い登録の知らせで生き返らないようにする。聴いたところは新しい順に500件まで
5. **書く頻度**: 登録の変化はすぐ、聴いたところだけの変化は30秒に1回まで（再生中は15秒ごとに変わる）

## 結果

- 中継につながっていない間の変化は、次につながったときに合わせる（その間に別の端末で同じ番組を外した・登録したときは、時刻の新しい方が残る）
- 端末の時計が大きくずれていると、古い変化が新しい変化に勝つことがある
- 中継の入れ替え（v1 と v2 は同じ配布物を見ているので、両方の再起動）が要る
