# 書き込み先のアカウントを DATASYNC_ID で確かめ、要求ごとにログインの世代で照合する

状態: 採用（2026-09-17、Phase 6 の準備 P6-0）

## 背景

重いレビュー（Codex、`dev/active/review-codex-heavy-2026-09-17.md`）で2つ指摘された。

1. 書き込み（評価・プレイリスト・再生履歴）の主体を識別していない。`obtainedAtEpochMs` は「今回のログイン」の区別で、アカウントの同一性ではない。ブランドアカウントや複数アカウントでは、画面で選んだ主体と書き込み先が一致する保証がない
2. アカウントの切り替えが1つの手続きになっていない。認証情報の差し替え・WaveSession の世代・再生サービスのキューとキャッシュの消去・画面の破棄が別々の購読で進み、隙間に旧アカウントの文脈で新アカウントの通信が起きうる

計画レビュー（Opus）で、書き込みの主体は `onBehalfOfUser`（= ログイン時に取る DATASYNC_ID の `||` より前）で決まり、チャンネルの有無に依らないことを確かめた。Pixel 3 の実アカウントで、accountsList の選択中のアカウントの `datasyncIdToken` の `||` より前が、保存している DATASYNC_ID と一致することを確かめた（キー名と真偽値だけ）。

## 決定

1. **アカウントの識別子は、正規化した DATASYNC_ID**（`||` より前）。WaveSession がログインの世代ごとに1本、accountsList の選択中のアカウントの `datasyncIdToken` と一致するかを確かめる
   - 一致 → Verified。書き込み・再生履歴・端末間の受け渡しは Verified のときだけ行う
   - DATASYNC_ID が無い・一致しない → Mismatch（`FailureKind.AccountUnverified`）
   - 通信の失敗など → Unknown。60秒後にもう一度確かめる
   - 読み取り（検索・ライブラリ・再生）は確認を待たない
   - 選択中のアカウントがちょうど1件のときだけ判定する
   - 受け渡しの前提（Verified・アカウントの HMAC の一致）は、受け渡しの調停役が確かめる（ADR-0009）
2. **切り替えは順序に頼らず、要求ごとにログインの世代で照合する**
   - WaveSession の `call`・`callWrite`・統計の送信は、呼び出し側が渡した世代が今の世代と違えば送らない
   - キューはキューを置き換えるたびにログインの世代を取り、続きの取得（next・プレイリスト）に渡す
   - キューの曲の URI（`wave://track/<videoId>?epoch=`）に世代を入れ、DataSource → StreamResolver → WaveSession で照合する。解決済みのキャッシュも同じ世代のものだけを使う
   - 評価の読み書き・プレイリストの編集は、操作を始めたときの世代で送る
   - AuthManager は認証情報と状態を公開する前に、同じ臨界区間で WaveSession の世代を進める（状態を購読する側が LoggedIn を見た時点で、世代は新しいログインに進んでいる）
   - キューが空のまま曲を足すとき・ログインしたときは、今のログインの世代に結び付け直す
   - 世代の無い曲は解決しない
   - 再生サービスのキューの消去・キャッシュの消去・保存ファイルの削除は、最終的にそろえばよい（その間に起きる要求は世代で止まる）
3. 識別子の値はログ・画面・端末の外に出さない。端末間で比べるときは、ペアごとの鍵での HMAC だけを暗号文の中で送る（ADR-0008）

## Considered Options

### チャンネル ID を識別子にする — 却下

チャンネルの無いアカウントでは取れない。書き込みの主体を決めるのは onBehalfOfUser で、チャンネル ID ではない。

### 切り替えを1つの状態機械にし、入口を閉じてから消して公開する — 却下

AuthManager（Default）・WaveSession（Default）・再生サービス（Main）・ExoPlayer のローダースレッドをまたぐ順序を保証するには、Main の後片付けを同期で待つ必要があり、サービスが無いときや Main が詰まったときに止まる。要求ごとの照合なら、同期が要る所は「世代を進めてから認証情報を公開」「照合と送信の開始に同じ世代」「Main で世代の取得とキューの操作を同じ処理で」の3点で済む。

## Consequences

- 書き込みの前に accountsList を世代ごとに1回呼ぶ
- DATASYNC_ID を取れないログインでは、書き込み・履歴・受け渡しができない（読み取りと再生はできる）
- 世代の照合で止まった要求は NotLoggedIn になる。キューは直後に再生サービスが消す
