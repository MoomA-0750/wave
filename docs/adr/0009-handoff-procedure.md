# 手元の端末が、再生中の端末からキューを引き取る

状態: 置き換え済み（[ADR-0010](0010-connect-v2-state-server.md)、2026-10-14 にコードと中継から削除）。もとは採用（2026-09-17、Phase 6。計画 `dev/active/phase6-plan.md` の P6-3、inner gate `review-p634-2026-09-17.md`、Pixel 3 と Galaxy Z Fold7 での実機確認を反映）

> 端末どうしで直接キューを頼む手順（Request・Snapshot・Ack・Cancel の封筒、HandoffTaker・HandoffGiver）は消した。キューのスナップショットの形（`HandoffSnapshot`）は、Connect v2 の家の状態の中身と、スマホと時計の間の再生の移動で今も使う。

## 背景

v1 は、手元の端末（B）が再生中の端末（A）から引き取るだけにする（K-0b）。押し付け・遠隔操作・状態の常時の同期はしない。通信路と鍵は ADR-0008。

中継はメッセージを保存しないので、相手が接続していなければ届かない。どの封筒も、落ちる・遅れる・前後することを前提にする。A と B が同時に鳴ること、どちらも鳴らないまま止まることを避けたい。

## 決定

1. **流れ**
   - B が `Request{handoffId, accountHmac, abandonedHandoffId?}` を送る（handoffId は B が発行）。abandonedHandoffId は、B がこの相手に出して取り込まなかった直前の要求。A がそれで一時停止したまま（Cancel が落ちた）なら、ここで取り下げる（暗号文の中なので中継は偽れない）
   - A は一時停止して snapshot を作り、`Snapshot{accountHmac, snapshot}` を返す（`:handoff-protocol` の HandoffSnapshot。受け取る側が形・件数・長さを検証する）
   - B は取り込んで再生を始め、`Ack` を送る（落ちる場合に備えて、新しい seq で3秒後にもう一度）
   - A は Ack で「引き渡した」と確定する
   - 断る・取り込めないときは `Cancel{handoffId, reason}`（`no_queue`・`account`・`not_adopted`・`timeout`・`incompatible` など）。A は Cancel を受けたときだけ再開する
2. **B（引き取る側）の状態は、Idle → Requested（20秒の期限）→ Adopting → Adopted**
   - 受けるのは、自分が発行して待っている handoffId の snapshot だけ（押し付けを受けない）
   - 期限切れ・アカウント不一致・検証で拒否・版違いの snapshot には Cancel を返す。取り下げた後に届いた snapshot でも、自分が最近出した要求への返事なら Cancel を返す
   - 取り込み中（Adopting）は期限で取り下げない。取り込みの途中で Cancel を送ると、A が再開して二重に鳴る
   - 取り込むのは、wave の画面が前面にあるときだけ。Android の前面サービスの開始の制限に当たらず、本人の目の前で再生を始めるため
   - 手元で再生中なら、置き換える前に画面で確かめる（debug の手順は確かめない）。引き取った側の直前のキューは残さない（K-5）
   - 相手が中継につながっていない（中継の `offline`、宛先と handoffId が一致）なら、待たずに知らせる
   - 待っていない snapshot にも、取り込んだ要求のものでなければ Cancel を返す（中継が要求を遅らせて届けた・B のプロセスが入れ替わった場合も、A を止めたままにしない）
   - 時間切れ・取り込めなかったときの Cancel は、落ちる場合に備えて2回送る
   - **B が引き取りを頼んでいる・取り込んでいる間は、相手からの要求に応じない**（`Cancel{busy}`）。互いに同時に引き取ると、両方が相手のキューで鳴る（outer gate）
3. **A（引き取られる側）は、snapshot を送ったら自動では再開しない**
   - 90秒の窓の間に Ack も Cancel も来なければ、「引き取られなかったかもしれません（一時停止しています）」と出す
   - snapshot を送り出せなかった（手元の送信の失敗・例外）ときは、一時停止したままにせず再開する
   - **中継が B を `offline` と返しても再開しない**（認証されていない。中継が snapshot を届けたうえで offline を偽れば、2台で鳴る。outer gate）。「届かなかったかもしれません（一時停止しています）」と出すだけにする。B は期限で Cancel を送り、次の要求にも取り下げを載せる
4. **A は「渡した（かもしれない）」キューを、もう一度渡さない**
   - snapshot を作った時点で「渡し済み」にし、Cancel か、この端末での再生で戻す
   - このプロセスで一度も再生していないキュー（保存から戻しただけのもの）も渡さない
   - 2026-09-17 の実機確認で、2台で行き来した後に、古いキューで相手の今の再生を上書きしたため
5. **A が要求を受けるのは、中継につながっている間だけ**
   - つながるのは、再生中と、一時停止から9分まで。受け渡しの窓の間は延ばす
   - 引き渡した後は、Ack の再送を待って5秒後に離れる
   - Android 12（Pixel 3）で、一時停止・画面オフのまま540秒後まで届くことを測った
   - Android 16（Galaxy）では、一時停止中も再生サービスが前面のまま（`procState=FGS`）で、通信は止められず、一時停止・画面オフから約6分後に引き取れた
   - B は、引き取り・ペアリング・解除の間だけつなぐ。中継の参照は数え、画面を離れても戻す
6. **アカウント**: 両端末とも ADR-0007 の Verified で、ペアの鍵でのアカウントの HMAC が一致するときだけ渡す・受ける。B は自分のログインで曲を解決する（認証情報は送らない）
   - 確かめたときのログインの世代を、そのまま取り込み・書き出しに渡す。A は、キューがその世代のものでなければ書き出さない。B は、今の世代が違えば取り込まず、取り込むキューもその世代に結び付ける（確かめた後にアカウントが切り替わっても、前のアカウントの結果で再生しない。outer gate）
7. **再生履歴（K-8）**: A は今の曲の聴いた時間（単調時計）と「送り済みか」を送る。B は同じ項目の最初の再生で、送り済みなら送らず、そうでなければその時間から数え始める。Ack を受けた A は、その曲の履歴を送らない。他の端末から引き取った再生も、YouTube Music の履歴に載る（ADR-0006）
8. **調停役（ConnectManager）の状態機械は、1本の Mutex の中でだけ触る**。受信・期限のタイマー・中継のエラーが行き違わない。snapshot の取り込みの間もロックを持つ。Ack の再送や解除の送り直しは、受信の処理を止めないように別に送る。1通の処理の失敗で受信を止めない
9. 同じ handoffId の Request は一度だけ処理する（直近32件を覚える）

## Considered Options

### A が snapshot を送ったら、すぐ再開の準備をする（タイムアウトで自動再開） — 却下

Ack が落ちると、B が鳴っているのに A も再開して二重に鳴る。止まったままの方が、本人がすぐ気づいて直せる。

### B が画面の外（通知・自動）でも取り込む — 却下

Android 12 以降は、裏から前面サービスを始められない（Galaxy で `startForegroundService() not allowed` を確認）。本人の知らないところで鳴らさない。

### 引き渡し済みを Ack を受けたときだけ立てる — 却下（inner gate M-6）

Ack が落ちると、古いキューをもう一度渡しうる。

### 中継の `offline` を、待っている要求にそのまま当てる — 却下（inner gate M-2）

別の送信（解除など）の失敗で、関係のない要求を取り下げる。中継が宛先・種類・handoffId を返す。

### 中継の `offline` で A を再開する — 却下（outer gate）

中継が snapshot を B に届けたうえで A に offline を返せば、2台で鳴る。再開は、ペアの鍵で認証された Cancel と、Request に載った取り下げだけにする。

### 互いに同時に引き取ったら、どちらかを勝たせる — 採らない（outer gate）

端末 ID や handoffId で勝者を決める規則は、状態が増える。v1 は両方とも断り、本人にもう一度押してもらう。

## Consequences

- 相手が中継につながっていないと引き取れない（再生中か、一時停止から9分以内）。画面でそう案内する
- 引き取った後、A は一時停止のまま、キューは残る。A でもう一度再生すれば、A のキューとして続く（その時点から、また渡せる）
- Media3 が一時停止のあと前面サービスを外した場合と、通知を消した場合の Android 15 以降の挙動は、まだ測っていない
- 3台以上での同時の要求、押し付け、再生中の曲の事前の問い合わせは v1 の外
