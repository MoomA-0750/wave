# 中継が家の再生状態を持ち、端末ごとの鍵で暗号化する（Connect v2）

状態: 採用（2026-10-14、本人の回答。案は 2026-09-18、Phase 6b。計画 `dev/active/phase6b-plan.md` v3、Opus の計画レビュー、Fable審査点⑤と再審査を反映）。Android・時計（スマホ経由）・Windows・Mac・iPhone の連携はすべてこの方式で動いている。v1（ADR-0008 のペアごとの鍵・ADR-0009 の直接の受け渡し）は 2026-10-14 に消した
置き換えるもの: ADR-0009 の「端末どうしで直接キューを渡す」手順（置き換え済み）。ADR-0008 の信頼モデルは保ち、ペアごとの鍵を端末ごとの鍵に替える

## 背景

Phase 6 v1（ADR-0008・0009）は、手元の端末が再生中の端末に直接キューを頼む形で、2台の通しまで確認した。残った弱点は2つ。

- 引き取られる側が、その瞬間に中継につながっている必要がある（再生中か、一時停止から9分。Android の裏の通信の制限もかかる）
- 引き取る前に、相手が何を再生中か分からない

本人の希望で、Spotify Connect と同じく中継（サーバー）が家の再生状態を持つ形にする（2026-09-17）。中継は信用しない前提を保つ（決定 L-1）。

## 決定

1. **家は1つ、端末一覧は署名付きの記録の鎖**（L-2・L-11・L-13）
   - genesis（最初の端末の自己署名、householdId = そのハッシュ）、add・remove を、その時点の家の端末が署名して積む
   - player を加えられるのは player だけ。controller（Phase 7 の PC、表示と操作だけ）は自分だけを外せる。最後の player は外せない
   - 端末は鎖を genesis から自分で検証し、検証した頭より短い鎖・分岐した鎖を拒む。中継は `prevHash` の CAS で追記を線形にし、追記のたびに `chain_changed` を配る
   - 中継の接続の認証は、鎖の今の端末から作る。家が無い間は、起動時の設定の鍵の端末だけが接続して家を作れる
   - 家を消すのは general-console の管理コマンドだけ（`docs/connect-v2-operations.md`）
2. **暗号化は端末ごとの鍵**（L-7）
   - 身元は Keystore の P-256 署名鍵、受け取りは Keystore の P-256 鍵交換の鍵（kx）。kx は身元鍵で自己署名する
   - 状態・命令は SealedDoc: 書き込みごとの内容鍵（AES-256-GCM）で本文を暗号化し、内容鍵を家の端末ごとに RFC 9180 HPKE（base、DHKEM(P-256, HKDF-SHA256)・HKDF-SHA256・AES-128-GCM）で包む。見出し・暗号文・宛先ごとの包みの全体に書き手が署名する
   - 見出しに、書き手が検証した一覧の頭（seq とハッシュ）を入れる。読み手は同じ seq でハッシュが違えば分岐として取り込まない。外した端末へは次の書き込みから包まず、書き手は新しい頭を見たらすぐ書き直す
   - 4KB 単位に詰め物をする
3. **中継が持つのは最新のカーソルとキューだけ**（D-4・D-5）
   - カーソル（数百バイト）は再生・一時停止・シーク・遷移・履歴の送信のたび、キュー（最大約 210KB）は変更のときだけ
   - 書けるのは中継の再生中の端末だけ、版の CAS。中継はファイルに書いてから返事をする
   - `storeId` を保存と一緒に永続化し、変わったら端末は本人に確かめるまで、その状態で止まらない・取り込まない（L-12）
   - 位置の経過は中継の時計で測る
4. **「最後に再生を始めた端末」が鳴る**（L-3・L-10）
   - 端末の時計は使わない。各端末は、再生を始めたときに見ていた最新のカーソルの版（sessionBase）と、そのセッションで最初に書けた版（sessionStartVersion）を持つ
   - 相手が自分のセッションを見てから始めていれば止まる。互いを見ずに同時に始めたときだけ、中継が claim に振った順番（claimOrder）で後の方を残す。順番が届くまでは判断を保留する
   - 止まる根拠は、署名を確かめた yield（自分宛）か、相手の再生中のカーソルだけ。中継の再生中の端末の値や版だけでは止まらない。一時停止のカーソルでは止まらない
   - アカウントタグ（`SHA-256(ラベル ‖ householdId ‖ DATASYNC_ID)`）が自分と違う端末の yield・カーソルでは止まらない（L-11）
5. **引き取り（transfer）**（L-4、D-7）
   - 引き取る端末は、最新の状態を開けてアカウントが一致することを確かめてから頼む。中継は前の再生中の端末を含む家の全端末に yield を配る
   - 前の端末がつながっていれば、一時停止して最後のカーソルを置く（`yielded`、CAS）。3秒で返事が無ければ、中継の最後の状態（外挿つき）から始める
   - 引き取った端末の最初のカーソルで確定する。引き取れない・切れる・10秒を過ぎたら、中継は再生中の端末を前の端末に戻す
6. **引き取られた端末の再生ボタン**（D-9）
   - 曲を選ぶのは新しい再生（claim）。再生ボタン（画面・通知・Bluetooth）は、同じアカウントの他の端末が鳴っていれば奪わない。前面なら引き取り、裏なら止めて通知する
   - 「鳴っている」は、最後のカーソルが再生中で、その端末が中継につながっている（presence）とき。presence は表示とこの判断だけに使い、止まる根拠にしない
   - 最新の状態をまだ受けていなければ、一時停止して中継につなぎ、受けてから決める。つなげなければ鳴らさず通知する
7. **加入**は v1 の QR と6桁の手順に、Hello（B の身元・kx・役割）と Confirm（householdId・一覧の頭・storeId・版の床）の拡張を足し、拡張のハッシュを両側の署名に入れる。Confirm は6桁の照合の前に送るので秘密を入れない
8. v1 と並べて動かし、2台の通しが済んだら v1 を消す（L-9）。2026-10-14 に消した（中継は v2 だけで起動する）

## Considered Options

### 家で1本の共有鍵 — 却下（L-7、Fable⑤ H1〜H4）

包みの送り手を認証しないと中継が偽の鍵を配れる。外すたびに鍵を作り直して配る競合がある。家の端末どうしでなりすませる。端末ごとの鍵なら、外すのは「次から包まない」だけで済み、書き手は署名で分かる。

### 中継が端末一覧を管理し、端末は信じる — 却下（Fable⑤ H2）

中継が一覧に端末を足せば、正規の端末がそこへ包む。端末が鎖を検証する。

### 端末の時計で「最後に始めた」を決める — 却下（L-10、Fable⑤ 再審査 高-1）

時計が5分遅れた端末は、再生を始めてもすぐ止められる。

### claim を版の CAS にする — 却下（Opus 高-1）

書き手の遷移と行き違うと、本人が始めた再生の方が負ける。通信が無い間に始めた端末は必ず負ける。

### サーバーを信用して平文で持つ — 却下（L-1）

## Consequences

- 中継にできること: 届けない・遅らせる・古い状態を返す（storeId を替えれば巻き戻しも、本人の確認つき）・再生中の端末 ID を書き換える・同時に始めた2台のどちらを鳴らすか選ぶ・書き込みの時刻の並び（曲の長さの並び）と暗号文の大きさ（4KB 単位）を見る
- 中継は、取っておいた yield を後から届けて、互いを見ずに始めた扱いの再生中の端末を止められる（claimOrder を偽る。届けないのと同じく可用性の範囲）
- 中継にできないこと: 状態を読む・作る、署名付きの命令・一覧の記録を作る、一覧に端末を足す
- 外した端末は、remove が書き手に届く前の窓の間と、中継が残していた最新の状態は読める
- 端末の kx 鍵が後から漏れれば、その端末に包まれていて中継に残っている最新の状態が読める（前方秘匿性は無い）。Pixel 3（SDK 31）では kx 鍵が Keystore のソフトウェア実装に置かれる（securityLevel=0、TEE の保護は無い）。さらに、その Keystore の鍵での鍵交換は1回ごとに操作の枠を漏らし、15回で wave の Keystore の操作（署名・AES も）がすべて止まり、再起動まで戻らない（2026-10-06、debug の keystore_probe で確かめた。署名と AES は100回でも漏らさない）。そのため Keystore がソフトウェアでしか守れない端末では、kx をアプリの中で持ち、Keystore の AES 鍵で包んでファイルに置く（守りの強さはほぼ同じ）。Fold 7（SDK 36）では TEE に置かれる（securityLevel=1）。X25519 はどちらの端末でも使えないので P-256 にした
- 通信を失ったまま鳴り続けた端末は、つながり直すまで止まらない（2台で鳴りうる、L-4）
- 同じ曲の再生履歴は、最後の状態から引き取った場合に二重に載りうる
- 遠隔操作（2026-10-06 追記）: 鳴っていない端末から、書き手へ「再生・一時停止・次へ・前へ・シーク」を、署名・暗号化した命令（kind=command）で送る。中継は書き手が送り主であることと大きさ（8KB）だけを確かめて家のほかの端末に配り、保存しない。受け手は、自分宛て・送り主が署名者で player・処理していない commandId・自分がセッションを持つ・同じアカウントタグ・送り手が見ていた版が「今のセッションで最初に書いた版」以上かつ自分の最新の書き込みから 20 版以内、のときだけ従う。同じ命令の doc の再送は開く前に捨てる
  - 中継にできること（命令）: 届けない・遅らせる（上の版の窓の内なら従う。一時停止中は版が進まないので、時間としては縛れない）・同じ窓の中で順番を入れ替える・どの端末がどの端末へ、いつ・何件命令を出したかを見る（種類と中身は暗号文の中）
  - 中継にできないこと（命令）: 命令を作る・書き換える・別の端末宛てにする（宛先・送り主・操作は署名つきの暗号文の中）・外した端末や別アカウントの端末の命令を通す
- 遠隔のキューへの追加（2026-10-15 追記）: 鳴っていない端末で「次に再生」「キューに追加」したら、書き手へ queue_add の命令（曲の `HandoffItem`・next・afterItemId）を送る。従う条件は遠隔操作と同じ。1件の平文は詰め物の1ブロック（4KB）に収め、曲が多ければ分けて、2件目からは前の件の最後の曲を afterItemId にして順をつなぐ。受け手は送り手の項目の ID のまま入れ、同じ ID がもうあれば入れない
  - 中継にできること（追加）: 分けた件の一部だけ届けない・順番を入れ替える（入れ替えると、続きは afterItemId が見つからず、自分で足した曲のかたまりの最後へ入る）
  - 「書き手」は、中継の再生中の端末の値ではなく、自分がセッションを持っていること。通信を失ったまま鳴っている端末も、つながり直せば命令に従う
  - 命令の見出しの時刻と受け手の時計の差が5分を超えたら従わない（2026-10-06 本人の決定。中継が取っておいて後から届けるのを時間でも縛る。順序の判断に端末の時計を使わない L-10 とは別の目的）
  - ほかの端末を映している間は、どの入口の再生ボタン（画面・通知・ロック画面・Bluetooth・Windows のメディアキー）も、その端末への命令になる。手元で鳴らすのは「この端末で再生」か曲を選んだときだけ（2026-10-06 本人の決定。§6 の「前面なら引き取り・裏なら止めて通知」は、映すものが無いとき（相手が同じアカウントで中継につながっていないとき）の再生ボタンに限る）。Android は映している間だけ MediaSession の再生器を、相手を映す音の出ない再生器に替える
- Windows の端末の鍵（2026-10-06 追記）: Windows の鍵の保管庫（CNG のソフトウェアの保管庫、今のユーザー）に書き出しできない鍵として置く。同じユーザーのほかのプログラムは、その PC の上で鍵を使えるが、取り出して持ち出すことはできない（TPM は機種による ECDH の対応が確かめられていないので使わない）
- テスト: HPKE は RFC 9180 付録 A.3 のベクタ、鎖・SealedDoc・止まる規則は単体、端末なしの多端末テストで本物の家の状態と敵対的な中継（yield を落とす・遅らせる・偽の chain_changed・保存の作り直し）を確かめる
