# セッションの失効は、ログインが外れたと確認できたときだけ判定する

## 決定

InnerTube の応答を次のように分類する。

| 応答 | 状態 |
|---|---|
| 401 | すぐに失効 |
| 3xx、`LOGIN_REQUIRED`、403、ログアウト相当の 200 | 疑い。`account/account_menu` で確認し、ログインが外れていると分かったときだけ失効 |
| 確認の `account_menu` が 3xx で `accounts.google.com` へ、または 401 | 失効 |
| 確認の `account_menu` に `actions` があるのに、アカウントのヘッダが無い | 失効 |
| 確認の `account_menu` にアカウントのヘッダがある | 有効に戻す |
| そのほかの 2xx | 状態を変えない |

- 疑い・失効を解除するのは、ログインが有効だと示す応答（アカウントのヘッダ）だけ。匿名でも成功する検索などの応答では解除しない
- 確認は同時に1本、30秒に1回まで（レート制限のときに負荷を上乗せしない）
- ログイン状態が変わるたびに「世代」を作り、状態は（世代, 状態）の組で原子的に更新する。古い世代の結果は新しい世代を書き換えない

## Considered Options

### 401・403・3xx・`LOGIN_REQUIRED` をすぐに失効にする — 却下

YouTube は有効なセッションにも bot チェックで `LOGIN_REQUIRED` を、レート制限で 403 を返す。
すぐに失効にすると、正常なのに再ログインを求めることになる。

### 2xx が返ったら有効に戻す — 却下

匿名でも成功する応答で、失効を誤って解除する。

## Consequences

- ログアウトした状態の `account_menu` の実際の形は、まだ観測できていない（wave はログアウト中に送信しない）。
  中身の分からない応答（`{}` など）では失効にしない
- Premium 音質の判定（固定の1曲で itag 141/774 を観測できたか）は表示用の診断値で、アカウントの資格の判定には使わない。
  再生時の音質は、再生する曲のフォーマットで決める
