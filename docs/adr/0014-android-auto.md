# Android Auto に wave を出し、車につないだら続きから鳴らす

状態: 仮採用（2026-10-13 夜。本人の確認待ち）

## 背景

本人から「Android Auto で使おうとして、ケーブルをつないで車を始動しても自動で再生が始まらず、Spotify が表に出てくる」と言われた。
wave の再生サービスは `MediaSessionService` で、Android Auto に出すための宣言（`com.google.android.gms.car.application`）も、
曲を選ぶ一覧（ブラウズ）も持っていなかった。車の側からは wave が音楽のアプリとして見えず、最後に使った Spotify が選ばれていた。

また、保存したキューは自アプリの画面がつながったときだけ戻していた（ADR-0006 の 8、F1 outer gate 指摘1）。
プロセスが無い状態で外から「再生」が届いても、画面を開くまで何も鳴らない。

## 決定

1. **再生サービスを `MediaLibraryService` にし、Android Auto の宣言（`automotive_app_desc`、media）を足す**
2. **一覧（ブラウズ）は Android Auto だけに見せる**
   - 相手は `com.google.android.projection.gearhead` で、つないできた uid がそのパッケージを持ち、onConnect で再生の操作を許した相手（信頼された・通知を読める）のときだけ
   - ほかの相手には、子の無いルートだけを返す（今までどおり再生の操作だけ。時計などの古い作りのアプリのつなぎ方を壊さない）
   - 一覧は「プレイリスト」（ライブラリのプレイリスト → 曲）と「最近再生した曲」（再生履歴）の2つ
3. **車で選べる曲は、一覧で渡した ID のものだけ**（`s:<親>:<位置>`）。任意の videoId は受け付けない（onAddMediaItems は今までどおり断る）。
   選んだら、画面で選んだときと同じキューの操作（playFrom）で流す。プレイリストなら続きのページ・最後からのラジオもそのまま
4. **再生の再開（onPlaybackResumption）で保存したキューを戻す**。受けるのは、onConnect で再生の操作を許した相手からの「再生」だけ
   （Android Auto・システムのメディアの操作。どちらもつなぐときに相手が確かめられる）。
   `MediaButtonReceiver` は足さない（明示的な Intent でプロセスの無い状態から再生を起こせる口は、今までどおり塞いだまま）
5. ログインしていない・保存したキューのログインが今と違うときは戻さない（今の戻し方と同じ）

## 結果

- 車につなぐと、Android Auto の設定（「音楽を自動再生」など）に従って、最後に使っていたなら wave が続きから鳴る
- 本人の端末の wave はストア経由で入れていないので、Android Auto の開発者向けの設定で「提供元不明のアプリ」を入れないと、車の一覧に出ない
- Android Auto には、ライブラリのプレイリストの名前と曲、再生履歴が見える（車の画面に出すため）
- 画像は今のところ出さない（車の側が https の画像を読めるかは未確認）
