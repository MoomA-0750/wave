# 端末間の受け渡しは、自宅の中継を信用せず、ペアごとの鍵で守る

状態: 採用（2026-09-17、Phase 6。計画 `dev/active/phase6-plan.md` の K-0a〜K-11、Fable審査点④と再審査、inner gate を反映）

## 背景

Phase 6 では、手元の端末が、再生中の別の端末のキューを引き取る（ADR-0009）。外出先からも受け渡せるように、端末どうしは自宅の中継を通してつなぐ（K-0a）。

中継は general-console の Docker で動かし、`tailscale serve`（HTTPS、funnel なし）で tailnet の中だけに公開する（K-1・K-2'）。tailnet の中の機器や中継そのものが乗っ取られることもありうるので、中継は中間者になりうると仮定する。送るもの（キュー・曲・位置・聴いた時間）は視聴データで、アカウントの識別子を比べる値も含む。認証情報（cookie・SAPISID・visitorData・DATASYNC_ID）は送らない（ADR-0002）。

## 決定

1. **信頼の根拠は、各端末が持つペアの一覧だけ**。中継の登録の一覧は、接続を受けるかの判断にしか使わない。自分のペアの一覧に無い送り手の封筒は、復号の前に捨てる
2. **端末の身元は Android Keystore の P-256 署名鍵**（`wave-device-identity-v1`）。端末 ID は署名公開鍵（SPKI）の SHA-256 の base64url。鍵を替えたら、ペアリングし直す
3. **ペアリングは QR と確認用の6桁で行う**（K-9・K-10）
   - A（中継に登録済みの端末）が QR `{v, pkA, eA, token}` を出す。eA はペアリングのときだけの使い捨ての P-256 鍵で、メモリに2分だけ置く。QR に秘密・中継の URL は載せない
   - A は中継に `pairing_open{SHA-256(token)}` を預ける。未登録の B は、未認証の `/pair` に token と Hello を送る。中継は tokenHash が一致した A にだけ転送する（1件・2分・8KiB）
   - B は使い捨ての eB で ECDH(eB, eA) をとり、そこから導いた鍵で `{pkB, 端末名, sigB(transcript)}` を暗号化して送る。A は sigA(transcript) を返す。身元鍵は署名にだけ使い、鍵交換には使わない
   - ペアの鍵（A→B、B→A、アカウントの HMAC 用）は、共有秘密と transcript から HKDF（RFC 5869、SHA-256）で導く。送る向きの鍵は、指紋の大小で決める
   - 確認用の6桁は B の画面に出し、本人が A に入力する。3回間違えるか2分たったら token を捨てる
   - アカウントの確認（ADR-0007 の Verified）と、ペアの鍵での HMAC の一致を、ペアリングの完了の条件にする。別のアカウントどうしはペアにしない。自分自身ともペアにしない
4. **中継への登録は、ペアリングのときに A が自動で行う**（K-7）
   - A は `sign("wave-relay-register-v1", host‖接続の nonce‖pkB)` を送る
   - A は中継の返事（成功・`register_failed`）を確かめてから、ペアを保存する
   - B は「続ける」で中継につながるか（= 登録されたか）を確かめてから、ペアを保存する。すでに別のペアで登録済みの端末では、これは承認の証拠にならない。片側だけに残ったペアは無害（相手から封筒が届かない）
   - 最初の1台は、中継の起動時の設定（`WAVE_RELAY_BOOTSTRAP_KEYS`）で登録する。これは締め出せない。登録は16台まで
5. **中継への接続は、署名による challenge-response で認証する**
   - 端末は `sign("wave-relay-auth-v1", host‖nonce)` を返す。host は中継が名乗る値ではなく、端末の設定の値を使う（別の中継に署名を流用させない）
   - 中継は、封筒の `from` が接続の端末 ID と一致するものだけを振り分ける
6. **封筒は AES-256-GCM**。`Envelope{v, suite, from, to, type, seq, handoffId?, nonce, ciphertext}` で、AAD に v・suite・from・to・type・seq・handoffId を入れる（handoffId の null と空文字は区別する）
   - `seq` はペアごと・向きごとに単調に増やす。送る前に予約して保存し、受け手は最後に受けた値以下を捨てる。判定に時刻は使わない
   - 中継が知るのは、端末の公開鍵、接続の有無、封筒の種類・宛先・handoffId・暗号文の大きさだけ
   - 中継は、宛先が接続していなければ `error{code: offline, to, type, handoffId}` を返す。これは送り手自身が付けた値だけで、送り手の待ちを正しく取り下げるために使う。**認証されていないので、再生を始める・再開する根拠にはしない**（中継が届けたうえで offline を偽れば、2台で鳴る。outer gate）
7. **保存する鍵とペアの一覧は、Keystore の AES 鍵（`wave-pairs-v1`）で暗号化して `noBackupFilesDir` に置く**。読めないファイルを空の一覧で上書きしない。読めない間は画面でそう出し、本人の操作でペアの一覧とその鍵だけを消して作り直す（ログインは消さない）
   - ペアリングの保存の直前に、アカウントを確かめたログインの世代が今も続いているかを確かめる（確かめた後に切り替わったら保存しない）
8. **ペアの解除と、中継からの締め出しは別の操作**（K-11）
   - 解除は手元の一覧からすぐ消し、相手に Unpair を送る。相手はペアの鍵で認証した UnpairAck を返し、送った側は **UnpairAck を受けてから**鍵を消す（中継が offline を返さないことは、届いた証拠にならない。outer gate）
   - 受け取るまで、中継につながっている間は1分ごとに、また相手から封筒が届いたときに Unpair を送り直す（2026-09-17 の実機確認で、相手が中継につながっていないと届かなかった）
   - Unpair を受けた側は一覧から消し、相手の再送に UnpairAck を返せるよう、鍵を7日だけ残す
   - 解除済みの記録を消すのは、鍵が同じときだけ（その間にペアリングし直した新しいペアを消さない）
   - 締め出し（`revoke`、署名付き）は紛失した端末のためのもので、ペアのどの端末からでも行える。v1 の画面にはまだ出さない
9. **中継のクライアントは、認証ヘッダを持つ HttpClient（ADR-0003）とは別の OkHttp**。ADR-0003 の許可ルートは変えない。中継の URL とホストは `local.properties` に置き、公開のソースに tailnet の名前を入れない
10. ログに出すのは、種類・件数・真偽値・短いエラーコードだけ。token・6桁・鍵・端末 ID・アカウントの識別子・本文は出さない

## Considered Options

### LAN の直接通信（mDNS など） — v1 では採らない

外出先から受け渡せない（K-0a）。中継を信用しない設計にしておけば、後から経路を足せる。

### Tink で鍵交換から AEAD までを組む — 却下（K-4 → K-4'）

鍵交換→HKDF→AES-GCM を組むと、安定 API の外の部品に頼る。Android 標準（Conscrypt）の ECDH・AES-GCM・HMAC を使い、HKDF だけを RFC 5869 のテストベクタ付きで書いた。

### X25519 — 却下

Pixel 3（Android 12）の Keystore で使えない（実測）。P-256 なら身元鍵を Keystore に置ける。

### 身元鍵で直接 ECDH する — 却下（K-9）

身元鍵を署名と鍵交換の両方に使わない。ペアリングのときだけの使い捨ての鍵で前方秘匿性を持たせる。

### 確認の数字を両方の画面に出して「一致」を押す — 却下（K-10）

本人が見比べずに押せてしまう。B の数字を A に入力させる。

### ペアの解除で、相手を中継から締め出す — 却下（inner gate M-7）

相手に別のペアがあれば、それも使えなくなる。締め出しは紛失のときだけの別の操作にする。

## Consequences

- 中継が乗っ取られても、読めるのは封筒の種類・宛先・大きさ・時刻だけ。封筒をなりすますには、ペアの鍵が要る
- 中継は、届けない・遅らせる・接続を切ることはできる。受け渡しの手順（ADR-0009）は、届かないことを前提に、一時停止したまま戻らない状態を残さない
- QR を写真で撮られても、2分と1回・6桁の入力（本人が A を持っている）が要る
- 端末の身元鍵は、アプリを入れ直すと変わる。そのときはペアリングし直す（中継の古い登録は締め出しで消す）
- Tailscale の分割トンネルで wave が対象外だと、中継に届かない。画面では「Tailscale に接続しているか」を案内する
