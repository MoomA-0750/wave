## 3. 改善案（推す順）

### 案 1: アルバムの検索で一致しなければ、曲の検索の行のアルバムから候補を作る（推す）

- 中身: `MatchOneAsync` の Album で、`RankAlbums` の結果が一致（`StatusOf == Matched`）でなければ、同じ語で `SearchSongsAsync` を引き、各行の `Song.Album`（題と browseId）と `Song.Artists` から `AlbumSummary` を作って（補足は「アーティスト • アルバム」の形）`RankAlbums` で点を付け、`Merge` で合わせる。browseId の重なりは除く。頼む回数はアルバムの見つからない・要確認 1 件につき 1 回増えるだけ
- 29 件への効き目: A1・A2 の 20 件で正解が候補の 1 位に出る。そのうちアーティストが比べられて合う **15 件**（#0〜3, 5〜8, 10〜15, 26）はそのまま一致。#20〜22・#25 の 4 件はローマ字名なので、別名（`NameAliases`）を学んでいれば一致、無ければ要確認。#19 は案 4 と組めば一致
- 見つからない 49 件への効き目: 29 件のうち 20 件は候補が付き（見つからない → 一致か要確認）、**見つからないは 49 → 29 前後**。要確認（約 375）のうちのアルバム（11-22 の前の数え方で 177 件のうちの残り）にも、「正解がアルバムの検索に無く、別のアルバムが中くらいの点で 1 位にいる」ものなら効く。何件かは今の session を使った試し（下の確かめ方）で数えるまで分からないが、A1 のようなシングルは同じ傾向が多いはずなので、数十件の見込み
- 誤一致の恐れ: (1) 同じ題で同じ人の別の版（通常盤・アニメ盤・初回盤、#7・#8 のような「同じ曲の入った別のアルバム」）。題を比べるので、題が違えば下がる（#7 は 1 位の「World Atlas」でなく 3 位の正解が上に来る）。題まで同じ別の版は今のアルバムの検索と同じ程度の恐れ。(2) アルバムの題と曲の題が同じとき、Spotify のアルバムに対して同じ題のシングルを選ぶ。気になるなら、曲の検索から作った候補は「点が高くても、アルバムの検索に出た候補の点を超えたときだけ」上に置く、または補足の種類（シングル・アルバム）が分からないので確か（Sure）の条件を「アーティストが合う かつ 題が 0.9 以上」と少しきつくする
- 変える所: `windows/Wave.Core/Transfer/TransferRunner.cs` の `MatchOneAsync`（Album の分岐）。候補を作る小さな関数は `TransferMatcher`（例 `AlbumsFromSongs(IEnumerable<Song>)`）に置いて純粋な関数として試せるようにする。同じ考えで `MatchAlbumGroupAsync` も、アルバムの検索が一致しなければ、まとめた曲の 1 曲目の曲の検索の行のアルバムを試すようにできる（曲の項目の頼む回数が減る）
- 確かめるテスト: `Wave.Core.Tests/SpotifyTransferTests.cs` の `FakeWriter` で、アルバムの検索は空、曲の検索は「雨上がりの空とキミ / LiSA / アルバム MPREb_x」の行を返す形にし、Album の項目が `MPREb_x` で一致になること。別の版の誤一致の形（曲の検索の 1 位が同じ曲を含む別の題のアルバム、3 位が正解）で、正解が 1 位になること。アルバムの検索が一致したときは曲の検索を引かない（頼む回数が増えない）こと

### 案 2: 2 本目の検索語（別名・版の飾りを外す・アーティストを外す）

- 中身: 案 1 のあとでも一致しなければ、語を変えてもう 1 回引く。順は (a) アーティストを別名の書き方にする（今も `ArtistQuery` でしているが、学べていない名前もある）、(b) 題から版の飾りを外す（`-Complete ver.-`・`【アニメ盤】`・`(アニメ盤)`・`通常盤`・`初回限定盤`・`(vol.0)` の括弧など。ただし比べるときは外さない。版の違いは題の比べで分けたいので、外すのは検索語だけ）、(c) アーティストが「feat.」を含む 1 つの長い名前（#27）なら「feat.」より前だけにする、(d) アーティスト入りの語で曲が 0 件なら、アーティストを外して題だけ（#17・#18 は「神ノ木高校チアリーディング部」を付けると 0 件、外すと出る）
- 29 件への効き目: #24（「三月のパンタシア ルビコン」で 1 位）、#18（アーティストを外して 1 位）の **2 件**。#17・#23・#27 は語を変えても上位に出なかった（#23 は 20 位まで見れば出る）
- 要確認・見つからないへの効き目: 曲の項目にも同じ (b)(c)(d) が使える。「Spotify だけの版」（decisions の「#23『放課後!』Mix」「KARAOKE」）は版が本当に違うので効かない。見込みは小さめ（数件〜十数件）
- 誤一致の恐れ: 検索語を緩めるだけで、点の付け方は変えないので小さい。アーティストを外した語は別の人の同じ題が出やすいが、その場合はアーティストの比べで下がって要確認になる
- 変える所: `TransferMatcher.AlbumQuery`・`SongQuery` の横に `RetryQueries(...)`（2 本目以降の語の一覧を返す純粋な関数）を足し、`TransferRunner.MatchOneAsync` で 1 本目が一致しなければ順に引く（1 件につき多くても 1〜2 回まで）
- 確かめるテスト: `RetryQueries` の単体の試験（「ルビコン -Complete ver.-」→「ルビコン」、「HoneyWorks feat. A・B」→「HoneyWorks」、別名があれば漢字の名前）。`FakeWriter` で 1 本目は空・2 本目だけ当たる形にして一致になること、1 本目で一致すれば 2 本目を引かないこと

### 案 3: 本人が手で選んだ組と、同じ題の項目から学ぶ

- 中身: (a) `NameAliases.Learn` は今、一致した曲（Track）だけから学ぶ。本人が手で選んだもの（`Manual`）はアルバム・アーティストの項目も入れ、本人が確かめた組として 1 回でも使う（いまの「2 回以上・ほかの 3 倍」の決まりは取り違えを避けるためで、本人の選びには取り違えが無い）。曲名が同じかの確かめも、手で選んだものは訳した題（#12・#19）で外れるので要らない。(b) その前提として、リンクを貼って選んだアルバムの補足にアーティストを入れる（`SpotifyTransfer.LinkCandidatesAsync` の `Summary` で `AlbumPage.Artists` を「種類 • アーティスト • 年」の形に入れる）。今は「Single • 2018」でアーティストが取れない。(c) 同じセッションの中で、題（Fold して飾りを外した形）が同じ別の項目がすでに一致・手で選んである ID を、その項目の候補に足す（点は題とアーティストで付け直す）
- 29 件への効き目: (a)(b) で「Sangatsu no Phantasia → 三月のパンタシア」（#24 の補足から今でも取れる）、「Nanamori-Chu☆Goraku-Bu → 七森中☆ごらく部」（#20〜23、補足を直せば）、「Haruka Tomatsu → 戸松　遥」（#25、補足を直せば）が学べる。これで案 1 の #20〜22・#25 の 4 件が要確認から一致になる（すでに曲から学べている名前なら上積みは無い）。(c) で #9・#16 に、#5・#4 の ID が候補として付く（アーティストが違うので要確認どまり。見つからない → 要確認で、本人は候補から選ぶだけになる）
- 要確認・見つからないへの効き目: 本人が手で選ぶほど、同じアーティストの残りが自動で決まる。手で選んだアーティストの曲がライブラリに多いほど効く（同じ人の曲・アルバムが数件〜十数件ずつ動く見込み）
- 誤一致の恐れ: (a) 本人の選びでも、客演の曲を選んだときに「Spotify の 1 人目 → YouTube の別の人」の組ができうる。今の `Learn` と同じく「どちらの側も文字の種類が違う名前が 1 つずつだけ」のときに限れば小さい。(c) 同じ題の別のアルバム（「Best」「Greatest Hits」のような題）を寄せる恐れがあるので、一致にはせず候補に足すだけ（Sure は今のアーティストの比べのまま）
- 変える所: `windows/Wave.Core/Transfer/NameAliases.cs` の `Learn`（Manual の項目を入れる、Album の Kind も見る）、`windows/Wave.App/Services/SpotifyTransfer.cs` の `LinkCandidatesAsync`（補足にアーティスト）、`TransferRunner.MatchOneAsync`（同じ題の項目の ID を候補に足す）
- 確かめるテスト: `Learn` に Manual のアルバムの項目 1 件（Spotify「Haruka Tomatsu」、補足「Single • 戸松　遥 • 2016」）を与えると組ができること、Manual でない 1 回だけの組はできないこと（今の決まりが残る）。同じ題の 2 項目のうち片方を手で選ぶと、もう片方の候補にその ID が付き、状態は要確認であること

### 案 4: 「Various Artists」を名前として比べない（小さい）

- 中身: Spotify のコンピレーションのアーティスト「Various Artists」（ほかに「ヴァリアス・アーティスト」「V.A.」）は、YouTube の補足のどの名前とも合わないので点が下がり、確かにもならない。アルバムの項目でこの名前だけなら、アーティストの無いアルバム（`album.Artists.Count == 0`）と同じ扱いにする（題が 0.9 以上なら確か）。検索語からも外す
- 29 件への効き目: #19 の 1 件（案 1 と組んで）
- 誤一致の恐れ: 題が同じ別のコンピレーションを選ぶ恐れはあるが、題 0.9 以上の条件があるので小さい
- 変える所: `TransferMatcher.ScoreAlbumSure`・`AlbumQuery`（と `SongQuery`）
- 確かめるテスト: 「Various Artists / 勇気のバトン 通常盤」と「勇気のバトン 通常盤 / 讃州中学勇者部, …」で一致・確かになること
