# AI コンテンツの識別: 設計（案。実装前）

2026-11-23。本人の方針（11-22）: 対象は曲とアーティスト、公式の表示（確定）と自前の手がかり（疑い）を見分けられる形で両方出す、「印・絞り込み」と「移すときの除外」は別の機能、外部の判定サービスは既定で使わず設定から足せる形。AI ラベルが付いた曲の特定は「やる」（設計を先に）。

## 1. 手がかりの出どころ

| 出どころ | 中身 | 確かさ | 状態 |
|---|---|---|---|
| YouTube Music の AI ラベル（2026-10-14〜。Fully / Partly / No Gen AI、「How this was made」） | 曲のプレーヤー画面に出る。応答のどこに入るか不明 | 確定 | 匿名の search・next・player（WEB_REMIX）では、AI 系 3 組の曲でも語が見つからなかった |
| Spotify の AI クレジット（DDEX） | 曲の詳細（クレジット）。配信元が申告した曲だけ | 確定 | Spotify の API・ZIP にあるか未確認（Web API の公開項目には見当たらない） |
| 自前の手がかり | 配信元・レーベル名、短期間の大量投稿、既知の AI アーティスト名の一覧 | 疑い | 未着手 |
| 外部の判定サービス | 例: Deezer の判定。曲名・音声を外へ送る | 疑い〜確定 | 既定で使わない。設定から足す |

## 2. AI ラベルが付いた曲を特定する手順（先にやる調べ）

1. 候補の曲を集める: AI 系として報じられたアーティスト（Xania Monet・Breaking Rust・Sienna Rose・The Velvet Sundown など）の曲、YouTube Music の「AI」関連の検索、本人が教える曲。
2. wave のデバッグ命令 `ai-label-probe <videoId>` を足す（ログイン済みの Client で next・player・browse の応答を取り、AI・synthetic・generative・disclosure・「How this was made」を含む箇所のパスと値だけを記録に出す。曲名・本人の情報は出さない）。匿名とログイン済み・WEB_REMIX と IOS_MUSIC など別のクライアントで比べる。
3. ラベルが付いている曲を 1 件でも見つけたら、応答の該当箇所（JSON のパス）を固定して `docs/` に記録し、`MusicParsers` に読み取りを足す。見つからなければ「公式のラベルは応答に出ない」と記録し、確定の手がかりは Spotify 側だけにするか、画面の表示（UI）を読む案を本人に出す。

## 3. データの形（案）

- `Song` と `ArtistSummary` に `AiContent`（None / Partly / Fully / Suspected、出どころの種類）を持たせる。確定（公式）と疑い（自前）は出どころの種類で分け、画面で見分けられる印にする（確定は塗り、疑いは枠線）。
- 印・絞り込みは表示だけの機能。「移すときの除外」は `TransferItem.Excluded` を使う別のスイッチ（既定は除外しない）。

## 4. 実装の順（本人の了承の後）

1. `ai-label-probe` を足して調べる（上の 2〜3。読み取りだけ。戻せる）
2. 読み取りを `MusicParsers` に入れる（テスト付き）
3. 曲・アーティストの印と絞り込み（見直し画面・ライブラリ）
4. 移すときの除外のスイッチ
5. 自前の手がかり（疑い）
6. 外部の判定（設定から。送る情報と費用を明記）

## 5. 本人が決めること

- 1 の調べ（`ai-label-probe`）を作ってよいか（ログイン済みの通信で曲の詳細を数十件引く。書き込みなし）
- 見つからなかったときの方針（画面の表示を読む・確定の手がかりは Spotify だけにする・識別を見送る）
